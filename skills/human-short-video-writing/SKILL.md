# 活人感短视频观点写作

把一个值得说的判断写成能直接念、经得起追问、对观众有用的中文短视频口播稿。默认交付成稿，不展示内部推演。

## 守住五件事

1. 一条稿只证明一个核心判断。冲突负责吸引注意，材料负责保住信任。
2. 现实内容只使用用户给出的材料、可核事实和明确标注的推断。不得替用户虚构亲历、原话、收入、客户、结果或心理。
3. 活人感来自说话位置、具体材料和真实取舍，不来自口头禅、粗口、错别字或假细节。
4. 观点稿必须帮助观众“赚钱”或“自洽”至少一项。纯知识说明、剧情故事和强销售转化属于近邻任务，不强行改造成观点稿。
5. 用户已有的事实、立场、语气和禁区优先保留。改稿不得为了制造金句偷换原意。

## 先判断任务模式

| 用户要什么 | 当前动作 | 交付 |
| --- | --- | --- |
| 从选题或材料写一条稿 | 创作 | 可直接口播的成稿 |
| 改现有稿 | 改写 | 保留原意的完整新稿；用户要求时附关键改动 |
| 只改开头、观点或结尾 | 局部优化 | 只交被要求的部分，必要时给 2～3 个方向 |
| 判断能不能发、有没有传播力 | 诊断 | 结论、主要证据、优先修改项；不默认重写全文 |
| 多条选题或开头比较 | 筛选 | 排序、淘汰理由、最值得继续的一条 |

信息已经够用时直接做，不让用户重走问卷。缺口会改变事实、立场或成稿方向时，合并成最多三个问题；用户明确要求直接出稿时，缩窄判断和篇幅，并明确保留未知，不编材料。

用户限定“只改前两句”“只给开头”或其他局部范围时，输出只含可直接替换的那一部分，不重贴未修改内容；只有用户要求拼成全文时才附完整稿。

## 工作流程

### 1. 固定任务约束

从上下文提取受众、平台、时长或字数、说话者身份、主题、目标、必须保留的信息、禁区和交付形式。用户没指定时采用这些默认值：面向对主题有兴趣但缺少背景的普通观众；60～90 秒；第一人称只在材料支持时使用；不加标题、分镜、表演提示和创作说明。

若任务依赖个人经历、现实人物、产品、数据、行业、健康、法律、金融或其他事实，读取 [references/evidence-and-boundaries.md](references/evidence-and-boundaries.md)。公开事实可能变化时先核验；个人经历只向用户取材。

### 2. 建立材料账本

在内部把材料分为四类：用户明确提供、可靠来源可证、合理推断、目前未知。每个主要段落至少由一条前两类材料或一条清楚说明前提的推断托住。

假设场景只能帮助解释，不能冒充证据。缺少能托住判断的材料时，先研究、追问或缩短；不能把一个抽象观点换几种说法来凑时长。

### 3. 选择一个可论证观点

创作、重写观点或优化开头时读取 [references/viewpoint-and-structure.md](references/viewpoint-and-structure.md)。先在内部形成若干候选，再选择证据最强、反驳空间清楚、脱离上下文仍能理解的一条。

核心判断需要同时回答：说给谁、在什么条件下、发生了什么关系变化、为什么成立。观点可以窄，不能比材料大。夸张程度不能高于论证强度。

### 4. 顺着观众的问题写

默认推进顺序如下，但不要写成六个整齐段落：

1. 开头给出具体冲突、代价、场景或核心判断。
2. 交代这个问题为什么与目标观众有关。
3. 用事实、经历、流程或因果解释判断。
4. 处理最强反方，不树愚蠢的假想敌。
5. 说明会改变结论的条件。
6. 把价值落到一个动作、选择或新的理解上。

让后一段接住前一段留下的问题。每一段都要增加新事实、新动作、新区别、新解释或新后果。同义改写不算推进。

### 5. 写给耳朵

- 一句话只承担一个主要动作或判断；主语和动作尽早出现。
- 新名词第一次说全，代词必须能找到对象，数字只保留听众需要记住的。
- 长短句跟着内容变化。一口气念不完就拆，连续短句像口号就合。
- 保留说话者自然的犹豫、补充和分寸，但不按固定间隔表演口语。
- 先写普通中文。金句从判断和材料里长出来，不靠套用反转句、三连排比和商业黑话。
- 不替观众总结已经能从动作和事实得到的情绪。

### 6. 完成改稿与终检

初稿完成后读取 [references/revision-and-diagnosis.md](references/revision-and-diagnosis.md)。按事实、观点、结构、口播、价值的顺序修；先救关键判断和材料，再清句子。

有可运行环境时，将成稿保存为 UTF-8 文本或通过标准输入运行：

```bash
python3 scripts/check_script.py 稿件.md --seconds 75
python3 scripts/check_script.py - --json
```

脚本只发现机械风险。警告需要结合用户声音和当前题材判断，不能因为警告自动改掉成立的句子。

交付前做两道内部终检：

- 观点终检：一句话能复述；正文实际证明了它；最强反方和边界已处理；离开上下文仍可理解。
- 价值终检：观众能获得一个可执行判断、少付一种代价，或更清楚自己的处境、责任和选择。

任一道明显失败，回到材料或观点修改。材料仍然托不住时，交付更窄的版本或说明缺口，不交空洞长稿。

## 改稿时保护用户原稿

先标记不可变项：事实、核心立场、人物关系、用户原句、语气强度和商业目的。只改用户授权的层级。

- “润色”默认不重搭结构，不另造观点。
- “重写”可以重排结构，但不能增加未经授权的事实。
- “去 AI 味”先处理空洞段落、假具体、机械转折和过度整齐，不把文本故意写粗糙。
- 用户指定必须保留的句式可以保留，除非它造成事实、安全或法律风险；此时说明风险并给替代。

## 诊断与交付

用户只要成稿时，只交成稿。用户要诊断时，给出“可发／修改后可发／不建议发”的结论，并按事实、观点、结构、口播、价值说明最关键的证据和修改优先级。不要用总分掩盖事实造假、核心判断不成立或高风险承诺等阻断项。

公开资料构成主要依据时，在文末列少量关键来源；个人经历和纯观点稿默认不附来源。不要把检索笔记、材料账本、候选观点和内部评分塞进成稿。

## 边界与停止条件

- 纯剧情、小说式故事、分镜、运镜和视频剪辑不处理。
- 直播带货、挂车卖课和以成交为主的广告脚本交给销售文案类 Skill。
- 知乎、公众号、论坛和其他长篇写作交给通用长文 Skill。
- 医疗、法律和金融题材只做一般性内容表达，不把口播稿伪装成个体建议或收益承诺。
- 对仍在世的人，不编造违法、疾病、私生活、动机和伤害性事实。
- 用户要求伪造经历、数据、背书或确定收益时停止该部分，并提供基于真实材料的安全版本。
