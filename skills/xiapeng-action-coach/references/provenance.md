## 冲突与口头表述如何处理

先核原话上下文、发言者及具体业务；有明确工具定义时不以口头简化覆盖工具。涉及外部概念查权威定义，涉及用户当前业务以真实数据与明确授权为准。不要把课堂参与者的一句提议写成已经批准的制度。

| 容易误用的表述 | 本技能的处理 |
|---|---|
| TAM/SAM/SOM与新客/新品象限直接对应 | 按P2分开市场范围和安索夫路径；定义边界后再判断 |
| 先填表才可行动 | 先填已知和假设，访谈正是补表的证据行动 |
| 一个案例得到CVP | 得到个案假设，仍需更多案例、反例与实际行为检验 |
| 人群一定用客观标签 | 标签帮助识别，行为/任务/条件决定交付；X3A补充行为分群 |
| 个人9分、任务自评分都叫NPS | 按题目和群体公式校准，不混用 |
| 高NPS决定LTV、卖什么都买 | 推荐信号不能替代新需求、支付条件、真实复购及成本 |
| 线上验证有效即可上线线下 | 仅可迁移部分需求证据，形式、成本与交付另验 |
| 敢重投、难复制就是优势 | 先证客户价值，再查could/would和自身投入回报 |
| 同框表达不需要客观正确 | 不采纳虚构比较；只使用可核实事实与有边界的收益 |
| 先低标准开始 | 适用于受限、可逆探索，不能免除已售承诺和关键质量 |
| 看到风险就应勇敢做 | 做事前推演，保留缩小或停止选择，预案不消除风险 |
| 不给答案、重复沟通 | 说明目的和结束状态，适时示范支持，用实际行为检验 |
| 21天、120天、8分、14天、5:1 | 均非本技能普适门槛；不把案例数字写成效果承诺 |
| 公司就是AI职场/生活方式平台 | 当时探讨的方向，不自动成为当前用户的战略事实 |

- **课堂方法**：六问、收益分类、四项验证、增长矩阵、比较维度、could/would、指挥官意图等。
- **整合解释**：阶段划分、获客/交付双循环、冲突协调与当前模块组织。
- **执行设计**：证据状态、表格解释、继续/修改/停止条件、统计分母、计算去重、授权边界、试验记录等。不能称作夏鹏逐字原话或公司已生效制度。
